# 后续建设规划 — 2026-09-14

## 目标和当前起点

目标仍是面向比赛的完整自动化漏洞分析工具，保留多组件、多漏洞族的扩展
范围。首批三个组件、44 个源文件不是永久上限。本规划按证据门槛推进，
不把模块数量、测试数量、API 提示或合成样例当作比赛完成度。

当前已经通过本地验证的链：固定版本与 profile → 真实双引擎批处理 →
证据绑定报告 → 35 条诊断/29 个复核组 → 原始源码窗口 → 145 项补证任务 →
函数/宏/同文件调用语法补证 → 扩展证据请求与本地LLM操作入口。
最新全量498项运行、494通过、4跳过；全部29组扩展请求预检完成，0次模型调用。
确认漏洞0；成功的线上 LLM 推理、真实 PoC、独立复现和产品级结论尚未验收。

赛题依据是用户提供的《OpenHarmony 开源代码漏洞挖掘》第二至第五节：
漏洞/CWE/CVE、可执行 PoC、版本影响、修复、报告、大规模性能与创新。
下面的工程顺序是项目规划，不是主办方给定的评分权重或时限。

## 近期自动工程主线

| 顺序 | 工作包 | 实施内容 | 完成门槛 |
| --- | --- | --- | --- |
| 1 | 补证进入受控研判 | 把新的片段目录接入模型请求契约；受控接收缺失证据建议，映射到明确白名单检索动作；保留预算和证据引用 | 至少一轮“证据 → 结构化研判 → 本地补证 → 再研判”可回放；伪造引用、请求越界和超预算均被拒绝；模型不晋升漏洞 |
| 2 | 语义规则正确性 | 收敛 `semantic_rules` 的固定邻近窗口和80行搜索，杜绝跨函数串联；按真实编译条件引入 AST 级函数、参数、调用及长度事实；未知显式保留 | 正反例覆盖同名函数、跨函数边界、宏分支、类型转换和生命周期；不得以词法关联宣称控制流证明 |
| 3 | 可扩展构建输入 | 规范化导入编译数据库与 profile；命令只解析为受限参数，不执行任意 command；接入更多组件并保留源/依赖版本 | 新组件能独立预检、运行和报告；缺失产品配置/头文件不会显示零漏洞成功；每批有真实覆盖/失败分母 |
| 4 | 多漏洞族规则与数据集 | 并行维护缓冲区/整数长度、空指针、UAF/生命周期、信息泄露、权限和逻辑边界；每个族准备缺陷/安全/修复前后对照 | 按漏洞族和组件分别统计质量；CWE有对应依据，CVE仅对可靠匹配输出；普通 API 提示、死存储不直接晋升 |
| 5 | 验证与修复链 | 先完成运行计划、环境描述、复现记录导入、分支比较和补丁回归契约；在明确隔离授权后接入真实执行 | 原始版本实际触发、独立复现、修复版本不触发且正常功能回归通过；构建失败/未知分支不当成安全 |
| 6 | 性能、对照评测和交付 | 记录阶段耗时、进程与子引擎资源、实际分析文件及失败数；测量后优化重复快照；维护手册与报告模板 | 基线引擎、规则增强、LLM增强三组可比较；完成干净环境复跑和五类赛题交付件，不夸大指标 |

顺序1、2是最接近当前补证数据的主线；组件接入及评测工具可在独立修改范围
内并行推进。遇到线上服务、设备或人工审核依赖，只停住对应的验收门槛，
不停止其他工程。不预先启动大量 Agent，也不以更换模型或放宽凭据边界解决阻塞。

3072个请求输出token、300秒socket超时。`plan`已对真实输入运行，0次模型调用。
函数/宏/调用语法片段现可进入受控请求和后续交接；缺失、省略、截断均保留。
历史请求保持原字节契约，不将窗口运行重写成扩展证据运行。

最新凭据重试仍在工具的输入检查阶段被拦截，未触达API，没有新的403或超时记录。
用户可依据 `docs/engineering/LLM_LOCAL_OPERATOR.md` 在已测通的本机服务环境运行。
下一步区分两个并行队列：用户完成首次真实在线调用；自动工程完成旧语义规则
边界修复、受限编译配置导入和基线/增强对照。首次真实回答回来后先独立验证，
再将缺失证据请求映射到白名单检索动作；不以格式正确代表推理正确。

保留用户选择的服务和 `grok-4.6` 请求标识，不擅自换模型。此前三次403是
历史请求结果；最近一次凭据输入在工具侧被拦截，没有新HTTP响应。用户本机
可用的反馈不能被旧状态推翻。

自动可做：扩展证据目录、输入预算、输出检查、离线模拟、重放和质量对照。
需要安排：能使用现有本地项目入口运行并产生不含密钥的回执的授权环境。
凭据仅在用户控制的运行时使用，不重新粘贴或写入仓库，也不规避工具检查。
一次成功回答只能证明接口与结构链通过，不能证明模型推理正确或漏洞成立。

## 不变的验收原则

失败不生成成功认证；恢复不绕过预算；旧结果不绑定新输入；同一缺陷的
多个工具观察不重复计为漏洞；引用存在不等于推理属实；检测不到不等于安全；
函数中出现检查不等于检查在实际路径上有效；补丁后不崩溃不等于补丁正确。

五类交付件持续维护：工具源码、技术说明书、使用说明和DEMO视频、含PoC/
影响/修复的漏洞分析报告，以及真实大规模性能说明。当前只有部分基础和
原型，最终材料不得写入尚未验收的能力。

不使用此前基于缩小组件范围的工期估算，不承诺新漏洞数量或未核实的官方
截止日期。每个工作包以运行回执、源码/输入哈希、负向路径和独立复核为完成依据。
