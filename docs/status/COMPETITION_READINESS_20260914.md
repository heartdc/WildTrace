## 剩余工程量估算

以下是规划估算，不是实测结果、交付承诺或新漏洞数量保证。假设源码和
隔离验证环境可用，范围先收敛到 1–2 个组件与少数高价值漏洞族，
一个有效人日按约 6 小时专注工程工作计算。

| 工作包 | 估计有效人日 | 完成判据 |
| --- | ---: | --- |
| 固定真实组件、依赖与构建基线 | 4–6 | profile 对应实际提交，目标/依赖可分析，源码和运行输入可追溯 |
| 安全性研判、检测规则与受控 LLM 流程 | 5–8 | 可达性/可控性/安全边界有依据；未知保留；有正反例与消融 |
| 真实 PoC、隔离验证、独立复现 | 7–10 | 真实目标稳定触发；能排除桩程序或环境导致的假象；独立重跑 |
| 分支影响与修复有效性 | 4–6 | 原版本复现、修复版本不触发且正常功能通过；未知分支不强判 |
| 实际性能、报告、手册、视频、打包 | 5–7 | 五类交付件可核查，干净环境可复跑，无未经验证的能力表述 |
| 小计 | 25–37 | 尚未计入环境等待和外部评审 |
| 工程缓冲 | 5–8 | 构建差异、集成返工与验收缺陷 |
| 合计 | **30–45** | 约 180–270 有效工时，外部评审与新漏洞发现不保证时限 |

单人全职、每周 5 个有效工作日约为 **6–9 周**；两人全职、职责可并行
约为 **4–6 周**，不能简单认为所有任务都能减半。若单人每天仅 3 小时，
同样工作量约为 **12–18 周**。访问阻断或设备等待应额外计入，无法保证上限。

从 2026-09-14 到设计稿中的 2026-10-22 有 38 个自然日。按这一日期，
单人完整交付风险较高；应压缩组件/漏洞族数量或并行分工，而不是压低
PoC、证据和误报门槛。该估算不保证发现新漏洞，也不包括奖励计划评审时延。
