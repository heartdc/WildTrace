# 离线长度规则与输入契约

本模块产生源码定位与候选关联，不提供编译器 AST、控制流、别名分析或漏洞结论。
当前按用户要求暂停 LLM 接入开发和调用；此链无需模型或密钥。

## 执行入口

`ohvul.semantic_rules.scan_semantic_files(root, relative_files)` 是带执行记录的入口。
主 CLI 的 `--semantic-files-from` 已使用此入口，而不是只投影候选列表。
`length_candidates` 和 `cross_function_length_candidates` 保留为兼容的列表接口；
它们拒绝输入失败，但不能用空列表证明分析完整或没有漏洞。

`candidates_to_audit_result` 单独调用时不知道实际读取范围，因此
`files_scanned=null`。不得由候选涉及的文件数推导扫描覆盖。

## 输入、范围与状态

输入必须是非空、无重复或别名的显式相对路径列表；拒绝越界、Git 元数据、
链接路径和不支持的扩展名。支持 C/C++ 源文件、头文件及显式 `.inl` 文件。
最多1024个文件，每文件最多2MiB，总读取预算64MiB；超过预算不生成空成功结果。
文件必须为普通文件，使用严格 UTF-8/UTF-8 BOM 解码。

读取成功后记录文件字节数与实际 SHA-256；读取或解码失败保留为 `input_errors`
与 `file_results`，不计入成功覆盖。全部成功读取为 `completed`；部分失败为
`partial`；全部失败为 `input_error`。主 CLI 拒绝失败语义阶段的成功发布。
文件字节在分析后再次核对；显式清单字节也在主 CLI 发布前再次核对。

执行状态与语义覆盖分开：`analysis_coverage` 为 `lexical_only` 或
`partial_lexical_analysis`，后者带 `analysis_issues`。预处理条件、无主函数范围、
不明确的调用目标、复杂参数与长度来源未知都不能变成安全结论。
即使 `completed` 且零候选，也只代表已完成声明的词法步骤。

## 候选规则

- 使用已匹配函数体边界，不再向下固定搜索80行，也不把函数外的来源/检查借入。
- 参数仅在顶层逗号处分割，保留多行、嵌套调用与原始偏移。
- memcpy/memmove/strncpy 的大小参数索引为2，snprintf 为1；显式标准命名空间
  写法可以归一化，不将任意命名空间或成员函数视为同名标准 API。
- 跨函数候选只在选定文件集合中存在唯一可用词法定义时考虑，按实际形参位置
  关联调用实参；静态函数不会从其他文件绑定，同名重载/成员调用不强行选择。
- 来源仅支持直接长度调用或同一调用者中最近一次简单赋值的词法观察。
  已观察到的覆盖赋值、增减、地址逃逸、简单遮蔽或被调用者参数改写会阻止关联。
- 原始来源行由真实调用位置取得，不再猜测为调用行减一。两个参与文件都绑定摘要。
- 普通复制/长度提示不默认标为 CWE-120；没有分类依据时保持 CWE 未知且绑定到证据。

以上不是完整 C/C++ 解析。模板/部分比较表达式、复杂参数、宏求值、类型转换、
别名、异常路径及全部遮蔽情形仍需要编译器事实；同文件检索也不是完整调用图。
检索不到来源只会留下未解析事项或局部候选，不证明数据不传播。
同一位置的局部候选和跨函数候选不是两个已确认漏洞。

## 快照和验收范围

文件摘要来自实际读取字节。可选 `source_snapshot_sha256` 由调用方提供，
投影或单独API不会替调用方证明整个根快照真实。主 CLI 和本轮真实验收脚本
分别执行根快照前后核对。普通哈希不是签名、不可变挂载或多文件事务。

测试只使用合成输入和模拟接口。真实验收对既有 profile 的44个文件做本地
读取与词法分析，没有重新调用 Clang/clang-tidy、模型或执行目标程序。
