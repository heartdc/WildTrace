# 证据校验契约

## 目的与使用

离线检查保存结果是否存在证据摘要不一致或悬空引用。读取保存文件，不读取文件中记录的源码路径，不执行源码。

```powershell
python -m ohvul.cli C:\path\to\source --output result.json
python -m ohvul.verify result.json
python -m unittest discover -s tests -v
```

成功返回 0，输入损坏或不支持返回 1。扫描输出格式为 0.3，证据格式为 1。旧 0.2 结果没有可重新计算的完整记录摘要，因此明确拒绝，需重新生成；不要静默补写为已验证。

## 记录与哈希

证据标识为 EB- 加完整 SHA-256。摘要覆盖除 evidence_id 自身外的序列化字段，采用排序键、紧凑 JSON、UTF-8 和禁止 NaN 的编码。artifacts 字段保存观察值的规范化 JSON 摘要，不是可执行产物或物理文件的哈希。

证据校验同时检查静态候选片段、位置与证据一致，以及静态/元数据引用存在。相同内容的证据允许重复引用。元数据当前仅检查记录 ID 关联，尚未绑定全部描述、组件标识和数据库原始快照。

## 可信边界

普通哈希可检测未同步更新摘要的变化。它不是签名或防篡改存储，不能抵御同时修改数据和摘要，也不能证明来源真实、漏洞成立、扫描范围完整或 OpenHarmony 平台受影响。现有输出写入没有事务和覆盖保护，须避免将输出指向已有源码文件。
