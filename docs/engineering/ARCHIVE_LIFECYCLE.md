# 审计归档生命周期策略

## 状态

归档分为 `active`、`sealed`、`superseded` 三种逻辑状态。当前工具只生成内容归档，不自动改变状态。

- `active`：可继续追加同一任务的新事件，但已有归档文件不可覆盖。
- `sealed`：人工确认内容完整后只读封存，不允许追加或替换。
- `superseded`：由人工创建了新批次替代，但原归档仍保留，只记录替代关系。

## 保留与删除

默认永久保留原始日志、检查点、扫描结果、报告、审核记录和归档摘要。工具不提供自动清理、定期删除或覆盖历史记录的功能。删除必须由人工在文件系统层执行，并在外部项目记录中留下原因、操作者和时间。

## 封存要求

封存前应完成：

1. `journal_archive_verify` 通过。
2. 相关报告、批次审核和 `review_chain_verify` 通过（如存在）。
3. 检查点与结果通过 `ohvul.verify --checkpoint`。
4. 记录源码快照、工具版本、规则版本和输入元数据是否完整。

封存是流程状态，不是密码学签名。当前没有防篡改存储或身份认证。

## 恢复与替代

恢复使用新 task/retry 检查点，不改写 sealed 归档。需要修订时生成新批次和新归档，并在人工说明中引用旧归档摘要；不得静默替换原始文件。

旧日志缺少时间戳时保持原样，不能通过迁移工具猜测时间。需要补充的信息以新审核记录追加。

## 封存标记

seal_schema 0.1 是独立的只读流程标记，绑定归档摘要和人工操作者信息。生成标记不会自动把归档移动、删除或设为不可读；当前没有身份认证或密码学签名。

## 独立标记生成命令

```powershell
python -m ohvul.archive_seal_record archive.json seal.json --operator NAME --reason REASON
python -m ohvul.archive_seal_verify seal.json archive.json
```

先验证归档结构、事件任务 ID、类型、筛选约束和摘要，再生成独立标记。生成命令仅证明当前归档满足这些检查，不代替上述封存要求中的整个审计链验证。NAME 与 REASON 由调用者填写，不是经过认证的身份或审核事实。

seal.json 必须不存在，父目录必须已存在；命令不提供覆盖开关，也不更改归档权限。原始归档保持不变。新文件写入中断可能留下无效标记，校验失败时不能宣称封存成功。归档原有 --force 能力仍存在，因此本节“不可覆盖”是流程要求，不是全系统强制策略。

测试证据：独立生成与校验、原文件字节不变、拒绝重复输出、拒绝覆盖源归档、拒绝损坏归档均通过。本轮总计 68 项，66 通过，2 项因符号链接能力不可用跳过。
