要
软件系统已成为现代社会运行的基石，但日益严峻的网络威胁使得软件安全问
题不容忽视。传统的自动化代码安全检测技术，尤其是静态程序分析方法，在检测效
率与覆盖率上具有优势，但常常面临误报率高、难以处理复杂代码结构以及对新缺陷
识别能力有限等问题。
为了克服这些局限性，结合传统程序分析引擎的代码分析能力和大语言模型的
代码理解能力，本文提出了一套代码安全检测方案，能够降低检测成本，提高检测和
修复效率。本文主要贡献及创新点如下：
在代码建模方面，基于图数据和向量数据，本文给出了一种代码知识图谱构建与
代码信息检索方法，此方法综合利用图数据与向量数据对代码语义进行建模，能够准
确提取和表示代码的结构和语义信息。
在检测算法方面，结合大语言模型的代码理解能力与指针分析技术，本文在原有
污点分析方法基础上给出了一种增强型代码安全检测算法，本方法能够有效提高传
统静态分析方法对风险代码的覆盖率，实验结果表明本方法能够有效补充污点转移
规则，并检出传统方法难以检测的用例。
针对检测报告，本文提出的基于大语言模型的检测结果优化方法，首先能够利
用大语言模型对检测报告进行误报缓解，其次本方法还会对检测报告内容进行扩展，
提供漏洞成因、修复建议和测试方案等信息，为开发人员与安全人员快速理解扫描结
果提供详实的资料。实验结果表明本方法能够显著降低误报率，在SQL 注入、命令
注入和路径遍历漏洞的检测中误报率降低了约29%-45%。
除了上述分析阶段的方法外，为了探索大模型技术在代码安全检测任务中的可
能性，本文提出并设计了一个代码安全检测智能体方案，以模型上下文协议（MCP）
技术为基础，利用大模型根据代码特征和任务需求自动对多种分析工具进行调用，辅
助人类专家加快检测效率。
本文提出的方案覆盖了代码安全检测流程中的多个方面，以程序源代码作为原
始数据，综合利用传统程序分析方法与大语言模型完成代码安全检测任务，本文为软
件安全检测领域提供了一套新的智能化解决方案，推广了AI 在代码安全检测场景中
的边界，有效提升了检测效率和准确性，降低了误报率，为开发人员和安全人员提供
了更高效、更准确、更智能的代码安全检测方案。

ABSTRACT
Modern software systems have become the cornerstone of societal operations, but the in-
creasing complexity and severe cyber threats make software security issues impossible to ig-
nore. Traditional automated code security detection technologies, especially static program
analysis methods, have advantages in detection eﬀiciency but often face challenges such as
high false positive rates, diﬀiculty in handling complex code structures, and limited ability
to identify new defects. To overcome these limitations, this study explores a novel intelligent
code security detection solution that combines the static analysis capabilities of traditional
program analysis engines with the code comprehension capabilities of large language mod-
els.
This paper aims to achieve automation and intelligence in analysis tasks by leveraging the
code comprehension capabilities of large language models throughout the code security de-
tection lifecycle, thereby reducing detection costs and improving detection and repair eﬀi-
ciency. In terms of code modeling, this paper proposes a code knowledge graph construction
method based on code property graphs and semantic vectors. This method comprehensively
utilizes graph data and vector data to model code semantics, accurately extracting and rep-
resenting the structural and semantic information of code, and providing retrieval solutions
adapted to different scenarios. In terms of analysis algorithms, this paper proposes a taint
analysis algorithm based on large language models and pointer analysis. By embedding the
capabilities of large models into the static taint analysis process and leveraging the code
comprehension capabilities of large models, this method can supplement special taint prop-
agation scenarios that traditional static analysis methods struggle to cover. Experimental
results show that this method can effectively supplement taint transfer rules and detect vul-
nerabilities that are diﬀicult for traditional methods to find. After the analysis, the detection
result enhancement method based on large language models uses large language models to
mitigate false positives in detection reports. Experimental results indicate that this method
significantly reduces false positive rates, with reductions of approximately 29%-45% in SQL
injection, command injection, and path traversal vulnerability detection. In addition to miti-
gating false positives, this method also extends the content by providing information on the
causes of vulnerabilities, repair suggestions, and testing solutions, offering detailed materi-
als for developers and security personnel to quickly understand scan results. Beyond these

1.1 研究背景与研究动机
如今各类软件系统已经深入渗透到经济、政府、医疗、教育等各大领域，成为了
现代社会高效运行的基础。然而，随着软件复杂性的不断增加和网络威胁的日益严
峻，软件安全问题已成为一个不容忽视的全球性挑战。近年来，频发的数据泄露事
件、勒索软件攻击和关键基础设施遭受的网络入侵，不仅造成了巨大的经济损失，还
严重威胁到个人隐私甚至国家安全。根据Cybersecurity Ventures 的预测[2]，到2025
年，全球网络犯罪造成的年度损失将达到10.5 万亿美元，这相当于自然灾害造成的
损失的2.5 倍。这些数据突出了提高软件安全保护能力的迫切性。在此背景下，设计
更加准确的软件安全分析方法，开发更加自动化的软件安全分析工具，不仅是技术创
新的需求，更是保护数字经济和社会稳定的关键。
静态污点分析作为一种自动化分析技术，广泛应用于检测程序中的潜在安全漏
洞。静态污点分析是一种无需执行程序就能对代码进行分析的方法，它通过追踪潜在
的不可信数据在程序中的流动路径，来识别可能导致安全漏洞的代码位置。这种方法
适用于检测诸如SQL 注入、命令注入、服务端请求伪造等常见的安全漏洞。与动态
分析相比，静态污点分析能够在软件开发的早期阶段就发现潜在问题，大大减少了后
期修复的成本和风险。此外，静态污点分析能够全面覆盖代码路径，包括在正常测试
流程中可能未被执行到的部分，从而提供更全面的安全保障。
近年来，随着数据流分析、指针分析、符号执行等静态程序分析技术的发展，静
态污点分析的精度和效率都得到了显著提升。尽管静态污点分析方法在检测效率上
具有显著优势，并且在软件安全领域取得了显著成果，但其准确性常常受到程序复杂
性和分析方法局限性的影响，导致误报率高、分析规模受限等问题，如何解决上述问
题是目前研究的重点。由于现有的静态程序分析方法在灵活性和扩展性方面存在不
足，难以适应多样化的分析需求，所以人类专家在获取信息、操作工具以及理解代码
上下文等方面发挥着不可替代的作用。然而，高度依赖人类专家参与的局限性也显而
易见，例如效率低、成本高以及对经验的高要求。尽管现有分析工具能够在部分分析
场景下提供辅助，但在智能化方面仍存在不足，无法更高效的提高效率和节省成本。
随着机器学习、深度学习等智能技术的发展，静态代码安全检测技术有望向着更
智能、更高效、更准确的方向发展。静态代码安全检测流程中的多个步骤都可以使用
智能模型进行优化。例如在代码表示构建阶段，除了传统的抽象语法树、控制流图、
函数调用图等代码表示外，使用代码嵌入模型生成的向量表示能够为后续相关分析

的代码逻辑缺陷等。在初步检测完成后，可以利用智能模型从大量数据中学习到的代

修复先后次序。除了上述应用场景外，利用智能模型对漏洞报告进行增强也是一个有
实际应用价值的方向，例如生成具体代码的漏洞成因和修复建议方便开发人员有针
对性的进行漏洞修复，规划缺陷测试方案方便安全人员对漏洞进行定位和测试等。
近年来以基于Transformer 架构[3]的深度学习模型为漏洞检测领域提供了一种变
革性的方法。研究表明[4]，网络安全社区已经受到了大语言模型的积极影响，近年来
相关文章的发表数量大幅增加，贡献涵盖了漏洞定位、检测和分析等多个领域。在工
业界，大语言模型也在逐渐走向应用，例如2024 年DARPA 举办了人工智能网络挑
战赛AIxCC[5]，该赛事仅利用通用LLM（GPT 系列、Claude 系列和Gemini 系列）进
行漏洞检测、复现和补丁。
综上所述，研究结合大语言模型与传统程序分析技术的智能化代码安全检测方
法具有重要的学术价值和实际意义。本研究旨在通过在代码安全检测的全生命周期
利用大语言模型的代码理解能力实现分析任务的自动化、智能化，从而降低检测成
本、提高检测和修复效率。
1.2 自动化代码安全检测技术研究现状
本节对传统程序分析方法、智能程序分析方法以及大语言模型在代码安全检测
方面的工作进行了梳理，总结了各类方法的优势以及存在的问题，为后续本文方法的
提出奠定了基础。
1.2.1 基于静态程序分析的代码安全检测技术
利用静态程序分析进行代码安全检测系统普遍包含代码模型、分析规则和分析
引擎三部分。代码模型（如抽象语法树、控制流图、数据流图等）用来表示程序的结
构和语义。分析规则定义了代码安全检测的具体逻辑和模式，这些规则通常基于已知
的漏洞模式或编码规范，用于匹配代码模型中的潜在问题。分析引擎是执行静态分析
的核心组件，负责将代码模型与分析规则结合起来进行检测，它通过遍历代码模型，
应用分析规则，识别出潜在的漏洞，使用的算法包括控制流分析、数据流分析、污点
分析等。
近年来研究人员通过建立不同的代码模型、使用不同的分析算法构建了多个基
于静态分析方法的代码安全检测工具，例如Kim 等在2008 年提出了一种软件漏洞检
测器[6]，它接受描述漏洞模式的规则和程序源代码作为输入，并检测程序中模式的位

置和路径。除了使用源代码作为输入数据外，将代码转换为图数据后，使用图搜索算
法进行代码安全检测是另一种常用的方法，例如Tabby[7]提出了一种基于代码属性图
的新型数据结构，利用图数据库来查找Java 反序列化利用链。除了上述利用数据流
分析、图分析等进行代码安全检测的工作外，使用符号执行进行代码安全检测也是一
种常用方法，例如Trinh 等在2014 年提出的用于检测Web 应用程序中的漏洞的符号

为了解决传统静态分析方法存在的误报率高、难以处理复杂的代码结构等问题，
一些研究通过混合使用静态分析方法与动态分析方法进行优化，例如2014 年，Dis-
tefano 等提出的方法[9]将动态分析观察到的具体输入输出对抽象成动态规范，在后
续的静态分析运行中将这些动态规范作为补充信息来使用。交互式应用安全测试技
术[10]对应用程序进行插桩，在程序运行时监控应用程序的执行、数据流、控制流等
信息并综合利用动态分析和静态分析进行漏洞检测。
静态分析方法能够对程序源代码进行全面的自动化扫描，但是静态分析方法也
存在一些问题。例如误报率高，传统的静态分析方法往往会产生大量的误报，需要人
工进行审查和过滤，耗费大量时间和人力；对新缺陷的识别能力有限，传统的静态分
析方法依赖于预定义的规则或模式，难以识别新的或未知的缺陷；难以处理复杂的代
码结构，传统的静态分析方法难以处理复杂的代码结构（例如包含大量指针和函数调
用的代码）。虽然引入了动态分析方法进行优化，但是仍存在误报问题。
1.2.2 基于机器学习与深度学习的智能代码安全检测技术
为了克服传统程序分析方法的局限性，研究人员探索了基于机器学习的缺陷检
测方法。基于机器学习的程序缺陷检测方法将代码转换为可供机器学习模型处理的
特征向量，并利用训练好的模型来预测代码是否存在缺陷。这些方法通常使用机器学
习模型来学习代码的特征表示，并根据这些特征来预测代码是否存在缺陷。这些方
法通常使用代码的特征表示（例如抽象语法树、控制流图等）作为模型的输入，利用
机器学习算法（如支持向量机、随机森林等）进行代码安全检测。与传统方法相比，
基于机器学习的方法可以自动学习漏洞模式，并能更好地适应不断变化的威胁环境。
2014 年，Joshi[11]等使用朴素贝叶斯机器学习算法和基于角色的访问控制机制对SQL
注入漏洞进行检测。2015 年，Padmanabhuni 等[12]提出了一种结合静态分析和机器学
习的方法，用于预测x86 可执行文件中的缓冲区溢出漏洞。2018 年，Kronjee 等[13]提
出了一种结合数据流分析和机器学习来发现软件漏洞的新方法，他们利用对代码样
本应用数据流分析技术，包括可达定义分析、污点分析和可达常量分析等提取代码
特征并训练了多种概率分类器，用于预测代码中是否存在SQL 注入或跨站脚本漏洞。
2019 年，Sonnekalb 等的工作[14]将源代码转换为不同的表示形式例如词法单元流、抽

除了基础机器学习模型外，参数量更大、结构更复杂的深度学习模型在代码安

生新的代码表征，其保留了程序的逻辑（控制流和数据流）和程序的自然语言信息。

帮助开发人员发现漏洞原因。
基于机器学习与深度学习的缺陷检测方法的优点在于能够学习复杂的代码特征，
并具有较高的准确率。然而这类方法也面临一些挑战，例如数据需求量大，训练高质
量的机器学习模型需要大量的标注数据，而代码缺陷标注成本较高；可解释性差，深
度学习模型通常被视为黑盒子，难以解释其预测结果；泛化能力不足，当遇到与训练
数据差异较大的新缺陷类型时性能可能下降等。
1.2.3 基于大语言模型的新型智能代码安全检测技术
近年来，随着大型语言模型技术的发展，其在代码理解[21-22]、代码生成[23-24]、代
码转换[25]等方面表现出的强大能力让进一步提高代码安全检测系统的智能化程度有
了新的方向。一些研究[26-28]表明，利用大语言模型强大的代码理解能力，将LLM 应
用于缺陷检测与修复能够取得优于传统分析方法的结果。
将大语言模型用作代码分析器。一些研究[29]直接将代码作为文本输入到LLM
中，并使用LLM 的文本分类或生成能力来识别漏洞。kouliaridis[30]等人比较了九种
最先进的LLM 在检测OWASP 移动安全项目列出的安卓代码漏洞方面的能力，并评
估了每个模型识别关键漏洞的能力，揭示了每个LLM 的优势和劣势，确定了影响其
性能的重要因素。为了适配特殊场景的漏洞检测任务，一些研究利用微调后的LLM
进行程序缺陷检测任务，例如Jiang 等人[31]对微调后的LLMs 在代码漏洞检测方面
的能力进行了系统研究，评估了4 个LLMs 在5 个不同的代码漏洞数据集上的性能。

训练的模型，6 个通用大型语言模型与3 个微调过的大语言模型，最终结果表明微调

结合传统静态程序分析与大语言模型。上述研究大多将代码视为普通文本输入
LLM，而缺乏必要的上下文信息和领域专业知识，这限制了LLM 在程序缺陷检测中
的准确性和可靠性。在利用LLM 进行代码生成方面，有研究[35]使用测试与静态分析
方法提高LLM 代码生成的质量，这给代码安全检测带来了一定的启发。为了进一步
提高基于LLM 的程序缺陷检测方法的能力，将传统程序分析与大语言模型进行结合，
充分利用LLM 的代码理解能力和传统分析技术的精确性，从而实现更有效和可靠的
程序缺陷检测来是未来研究的一个重要方向。例如LSAST[36]通过将传统的SAST 扫
描器与LLM 功能相结合，显著提高了LLM 在漏洞扫描方面的性能。IRIS 框架[37]利
用LLM 来推断污点规范和执行上下文分析，然后使用CodeQL 等静态分析工具进行
全库分析，并利用LLM 进行上下文分析，减少误报。LLift 框架[38]通过后约束引导
分析增强了路径验证能力，并利用一系列提示策略来提高LLM 输出的可靠性和一致
性。LLM4FPM[39]利用精确和完整的代码上下文来指导LLM 进行自动误报消除。
利用大语言模型辅助人类在静态程序分析中的工作，面临的主要挑战如下：首
先，如何构建精确的代码上下文，使大语言模型能够准确理解代码结构和语义。现代
软件系统通常包含大量模块和依赖关系，如何准确提取和理解代码上下文是一个挑
战。此外，不同编程语言的语法和语义差异较大，如何构建跨语言的统一上下文表示
是一个难点。其次，如何提供对代码审计过程中相关工具的调用能力，使大语言模型
能够像人类一样灵活操作工具。代码安全分析过程中涉及多种工具（如代码格式化工
具、关键字查询工具、代码结构分析工具、动态调试工具等），如何实现对这些工具
的灵活调用和集成，根据代码特征和任务需求，智能地调度和组合不同工具，以实现
最优的分析效果。现有方法在这两个方面的表现尚未达到实用水平，限制了其在实际
应用中的推广。在代码分析过程中，人类专家作为智能体具有获取信息的能力及操作
工具的能力，而代码作为关键上下文贯穿于分析过程中，要利用大语言模型对人类工
作进行辅助就需要构建精确的上下文并提供分析过程中的相关工具的调用能力。

2.1 知识图谱与程序表示
知识图谱是一种结构化的语义网络，用于描述现实世界中的实体、概念及其相互
关系。它以图结构为基础，节点代表实体（如人、地点、事物或抽象概念），边代表
实体之间的关系或属性。知识图谱通过将复杂的知识领域通过数据挖掘、信息处理和
图形绘制展示出来，揭示知识领域的动态发展规律，为学科研究提供有价值的参考。
它广泛应用于搜索引擎、智能问答、推荐系统等领域，帮助用户更高效地获取和理解
信息。
程序表示在静态程序分析中扮演着基础性角色，其重要性体现在为分析任务提
供结构化的语义信息。针对不同的分析需求，研究者需选择适当的程序表示形式，以
提取不同层次的程序语义。
2.1.1 知识图谱构建技术
知识图谱构建技术是一种将现实世界中的实体、概念及其关系进行结构化表示
的技术，旨在构建一个庞大的语义网络图。其构建过程通常包括数据采集、知识抽
取、知识融合、知识存储和知识推理等步骤。首先，从结构化、半结构化和非结构化
数据中提取实体、关系和属性，形成三元组数据。接着，通过知识融合技术整合来自
不同数据源的知识，确保知识的一致性和准确性。最后，将融合后的知识存储到数据
库中，并利用推理技术从已有知识中推断出新知识。知识图谱的构建方式主要有自顶
向下和自底向上两种，前者先定义本体和数据模式，后者则从开放链接数据中提取实
体并逐步构建本体模式。知识图谱技术广泛应用于搜索引擎、智能问答、推荐系统等
领域，极大地提升了信息检索和知识利用的效率。
近年来，基于大模型的知识图谱构建技术[40]逐渐兴起，该技术旨在解决传统知
识图谱构建过程中依赖人工编写规则模板和标注数据所导致的人力和时间成本过高
的问题。通过充分利用大语言模型在文本理解、知识抽取和上下文推理等方面的优
势，可以从大规模语料库中高效地提取实体、关系和属性等信息，从而构建领域知识
图谱。在此基础上，结合大语言模型的语言理解能力，能够实现更准确和可靠的文本
理解与推理，并应用于知识智能问答等场景。这种方法为知识图谱的构建与应用提供
了一种更可行和可持续的解决方案。

2.1.2 常见程序表示形式
抽象语法树（AST）是源代码语法结构的一种抽象表示，它以树状的形式表现编
程语言的语法结构，树上的每个节点都表示源代码中的一种结构。静态单赋值（SSA）
是一种代码中间表示，在这种表示中每个变量仅被赋值一次。控制流图（CFG）利用
数学中图的表示方式，表示计算机程序执行过程中所经过的所有路径。程序依赖图
（PDG）是程序控制和数据依赖的有向图，图上的节点表示程序语句，边表示这些语
句之间的依赖关系，PDG 常用于优化、调试和理解程序行为。调用图（CG）可以展
示计算机程序中函数之间的关系，每一个节点是一个函数，边(f, g) 表示函数f 调用
函数g，若其中有出现互相调用的环，表示程序中可能有递归调用。
除了上述表示形式外，将多种表示形式进行融合，得到的信息更完整的综合程序
表示形式在程序分析任务中经常被使用。过程间控制流图（ICFG）是融合了控制流
图和调用图，包含了函数调用和返回信息，连接了不同函数的控制流图。代码属性图
（CPG）是一种计算机程序表示，它通过属性图捕捉了句法结构、控制流和数据依赖。
代码属性图是通过合并其抽象语法树、控制流图和程序依赖图在语句和谓词节点上
得到的程序图表示。代码属性图可以存储在图数据库中，并使用图查询语言进行查
询。
通过对源代码中的各种信息进行组织能够构建出表达能力更强的程序表示形式，
即代码知识图谱[41]。代码知识图谱是一种大规模语义网络，表达了与代码相关的实
体/概念及其之间的各种语义关系。它旨在实现人、机器和代码之间的语义关联，是
实现智能化软件开发的基础。代码知识图谱在智能化软件开发中具有广泛的应用前
景。首先，它能够为理解用户意图提供强大的背景知识，支持知识和事实的逻辑推
理，有助于实现语义层面的搜索泛化。其次，基于知识图谱的代码推荐具有较强的可
解释性，能够帮助用户理解推荐结果，并支持推荐规则和流程的优化。此外，知识图
谱的引入还能为代码生成提供模板，通过融合模板和深度生成模型，能够为用户生成
满足意图的代码。总而言之，代码知识图谱展现出解决智能化软件开发过程中各种瓶
颈问题的巨大潜力，能够辅助开发人员把握软件的功能需求，理解代码语义，搜索和
匹配语义相似的代码片段。

2.2.1 基础理论
形式化方法（Formal Methods）是基于数学的特种技术，适合于软件和硬件系统
的描述、开发和验证。形式化方法采用各种理论例如计算机科学的基本原理，包括逻
辑演算、形式语言、自动机理论、控制理论、程序语义、类型系统和类型论等。
停机问题（Halting Problem）是逻辑数学中可计算性理论的一个问题。停机问题
就是判断任意一个程序是否能在有限的时间之内结束运行的问题。该问题等价于如
下的判定问题：是否存在一个程序P，对于任意输入的程序w，能够判断w 会在有
限时间内结束或者死循环。艾伦·图灵在1936 年用对角论证法证明了不存在解决停
机问题的通用算法。这个证明的关键在于对计算机和程序的数学定义，这被称为图灵
机，停机问题在图灵机上是不可判定问题。
抽象解释（Abstract Interpretation）是静态程序分析的理论基础，它可以被看作对
计算机程序的部分执行，获取关于它的语义信息(比如，控制结构、信息流) 而不进
行所有计算。
模型检查（Model Checking）是一种自动验证技术，由Clarke 和Emerson 以及
Quelle 和Sifakis 提出，主要通过显式状态搜索或隐式不动点计算来验证有穷状态并
发系统的模态/命题性质。
2.2.2 静态程序分析方法
控制流分析（Control-Flow Analysis）是一种静态程序分析技术，旨在研究程序执
行过程中控制流的转移路径。它通过分析程序的结构（如条件语句、循环、函数调用
等）来推断程序的可能执行路径，帮助理解程序的逻辑行为。控制流分析的核心目标
是构建控制流图（Control Flow Graph, CFG），其中节点表示基本块（连续的语句序
列），边表示控制流的转移。通过分析控制流图，可以检测不可达代码、识别循环结
构、优化程序性能，以及辅助编译器进行代码生成和优化。此外，控制流分析在程序
验证、安全分析和漏洞检测等领域也有广泛应用，是程序理解和分析的重要工具之
一。

2.2.4 静态程序分析的局限性
静态分析的精度与分析效率往往受限于不同的敏感性设置。以执行顺序的影响
为例，流敏感分析通过追踪代码的潜在执行路径来捕捉变量状态的变化，这种精细化
的追踪机制虽然显著提升了状态推断的准确性，但代价是算法时间复杂度呈指数级
增长。在实际工程实践中，当遇到包含多重条件分支的复杂控制流时，分析效率的下
降尤为明显。对于涉及多路径执行的情况，路径敏感分析试图穷举所有可能的逻辑分
支。理论上这种穷举策略能有效识别不同条件组合下的程序行为，但在面对深度嵌套
的if-else 结构或循环体时，路径爆炸问题会直接导致计算资源耗尽。上下文敏感分析
则聚焦于函数调用的动态特性。不同于简单的函数摘要复用，该方法为每个调用点建
立独立的数据流模型，这在处理递归调用或多态函数时展现出独特优势。但值得注意
的是，当某个函数在系统中被高频调用时（例如作为核心工具函数），这种细粒度分
析会引发内存占用的急剧上升，在安卓应用这类大规模代码基中尤为突出。
静态分析的局限性还体现在难以处理复杂的动态逻辑。在涉及指针和别名关系
时，静态分析工具难以精确追踪指针的指向和别名关系，容易导致误报或漏报。动
态内存分配的复杂性使得静态分析难以准确判断内存的分配与释放，尤其是在涉及
malloc、free 等操作时，容易忽略内存泄漏或悬垂指针问题。函数指针/虚函数调用的
运行时多态性使得静态分析无法在编译时确定具体的调用目标，增加了分析的难度。
除了上述问题外，静态分析工具还往往难以准确判断数组的越界访问，尤其是在涉及
复杂循环或动态索引时。
静态分析在处理某些语言特性和复杂场景时也存在一定的局限性。例如反射和
动态加载机制使得静态分析难以准确推断程序的行为，因为反射调用和动态加载的
类或方法在编译时无法确定，导致分析结果可能不完整或存在误报。异常处理的复杂
性也增加了静态分析的难度，因为异常路径通常依赖于运行时状态，而静态分析难以
模拟所有可能的异常场景。在并发特性方面，静态分析难以准确检测多线程环境下的
竞态条件和死锁问题，因为这些问题的发生依赖于运行时线程调度。库函数调用的局
限性在于静态分析工具可能无法深入分析第三方库的内部逻辑，尤其是闭源库。

器完成，负责解析代码结构。关键在于后续的语义分析阶段，它运用多种静态分析技
术（如控制流分析、数据流分析、类型检查等），在代码结构上进一步推断和验证程
序的逻辑意义、检查一致性，并提炼出关于程序运行行为的丰富信息，为软件开发中

3.1.2 代码向量化技术
向量形式的代码表示通过将代码的语法和语义信息编码到连续的向量空间中，它
能够捕捉代码的深层含义，克服传统基于文本匹配方法的局限性。近年来向量形式的

代码向量化技术如下：Code2vec[64]是一个神经网络模型，旨在将代码片段表示为连
续的分布式向量，它通过将代码分解为抽象语法树中的路径集合，并利用注意力机制
来学习和聚合这些路径的向量表示，最终生成一个能够代表整个代码片段的固定长
度向量。CodeBERT[65]是一个双峰预训练模型，旨在连接编程语言（PL）和自然语言
（NL），它基于Transformer 架构，通过结合掩码语言建模和替换token 检测的混合目
标函数进行训练,CodeBERT 利用双峰（NL-PL 对）和单峰数据，学习通用表示，以
支持自然语言代码搜索和代码文档生成等NL-PL 应用。CodeT5[66]是一个统一的预训
练编码器-解码器模型，用于代码理解和生成。它基于T5 架构，并利用标识符感知预
训练，使模型能够区分代码中的标识符并恢复它们，CodeT5 还利用双模态双重生成，
通过用户编写的代码注释，实现更好的NL-PL 对齐。GraphCodeBERT[67]是一个预训
练的编程语言模型，它通过利用代码的内在结构来学习代码表示，GraphCodeBERT
使用数据流来编码变量之间的关系，该模型基于Transformer 架构，并引入了图引导
的掩码注意力机制，以及两个新的结构感知预训练任务，分别是数据流边缘预测和变
量对齐。

3.1.4 检索召回技术
检索召回技术是信息检索系统中的核心环节，主要负责从海量数据中快速筛选
出与用户查询相关的候选集。其目标是在保证高效性的同时，尽可能覆盖所有可能的
相关文档或信息。常见的召回技术包括基于关键词的倒排索引、向量化检索、图检索
等。这些技术通过不同的方式衡量查询与文档之间的相关性，能够在毫秒级时间内从
大规模数据集中返回初步的候选结果，为后续的排序和精排阶段提供基础。检索召回

识库中查找和获取相关信息。图检索技术通过分析知识图谱中节点和边的结构，能够
高效地查询复杂的关联信息，并从语义层面理解用户意图，提升检索质量。该技术广
泛应用于搜索引擎、智能问答、推荐系统等领域，帮助用户更精确地获取所需信息。

法等）、启发式算法（如用于求解多源、无负权边的最短路径的A* 算法）。

3.2 代码图数据与向量数据应用场景分析
代码图表示专注于代码的结构化分析，提供了一种直观且深入的方式来理解和
分析代码的内部结构与关系。通过可视化代码的调用关系、继承关系和数据流向，代

评估其耦合程度，为代码维护和重构提供依据。通过分析控制流和数据流，代码图表

测不可达代码、无限循环、异常处理缺失等逻辑缺陷；在数据流分析方面，能够追踪
变量的定义-使用链，发现未初始化使用、空指针解引用、内存泄漏等问题。特别对
于安全风险，代码图通过构建完整的程序依赖图，可以识别潜在的注入漏洞、权限越
界、敏感数据泄露等安全隐患。

实现了基于相似度的快速检索和比较。代码向量表示的主要应用包括高效的代码复

指针分析是一种用于追踪程序中指针变量的值和引用的技术，它通过分析指针

可能指向的对象或内存地址，这对于程序优化、漏洞检测和编译器设计具有重要意
义。指针分析算法根据是否考虑上下文分为上下文不敏感的指针分析算法与上下文
敏感的指针分析算法。
上下文不敏感的指针分析是一种在程序分析中不考虑函数调用上下文信息的指

的流不敏感上下文不敏感算法，虽然效率高，但精度较差。

4.1.4 污点分析算法
基于集合传播的污点分析算法核心思想是通过集合运算追踪污点数据在程序中
的传播路径。该算法首先识别污点源（如用户输入）和污点汇聚点（如危险函数调
用），将污点源数据标记为初始集合。随后，在程序的控制流和数据流分析过程中，通
过集合的并、交、差等运算传播污点标签：若某操作涉及污点数据，则其结果集被加
入污点集合；若经过无害处理（如加密），则从集合中移除。
基于图传播的污点分析算法通过将程序抽象为数据流图，并在图上进行污点的
传播来跟踪敏感数据的流向。该算法首先识别程序中的污点源（如用户输入），将其
标记为污点节点，然后根据预定义的传播规则，沿着数据流图的边递归地传播污点
标记。在传播过程中，算法会考虑直接赋值、算术运算、函数调用等不同类型的数
据流关系，并相应地更新节点的污点状态。当污点数据到达敏感操作（称为沉降点）
时，算法会发出安全警告。这种方法能够有效地发现程序中的安全漏洞，如SQL 注
入、跨站脚本攻击等，是现代程序安全分析中的重要工具。
P/Taint 污点分析算法[74]是一种统一的指针分析和污点分析方法。这种方法的核
心思想是将污点信息表示为特殊的抽象对象，并利用现有的指针分析算法来同时计
算程序中的指针指向关系和信息流。通过这种方式，P/Taint 可以复用指针分析领域
的已有成果，例如上下文敏感性和反射分析，从而提升信息流分析的精度和召回率。

4.2.2 使用大语言模型优化静态程序分析算法
近年来，随着大模型技术的快速发展，其在静态程序分析领域的应用逐渐展现出
巨大的潜力。特别是在解决传统静态分析算法中的漏报问题上，大模型技术提供了
新的思路和方法。传统的静态分析工具通常依赖于预定义的规则集来识别潜在的安
全漏洞，但这些规则集往往无法覆盖所有可能的场景，尤其是在面对复杂的代码库
或新兴的编程范式时。通过大模型，分析工具可以动态生成更全面的Source 和Sink，
从而减少漏报的可能性。例如，大模型可以根据代码的上下文语义，识别出一些非标
准的输入输出点，这些点可能在传统的规则集中被忽略。除此之外，大模型还可以用
于生成污点转移规则。在静态分析中，污点分析是一种常见的技术，用于追踪数据流
中的潜在安全问题。然而，传统的污点转移规则通常是手动定义的，难以应对复杂的
代码逻辑或动态行为。通过大模型，分析工具可以自动生成更精确的污点转移规则，
特别是在处理复杂的数据流或跨函数调用时，大模型能够更好地理解代码的语义，生
成更准确的规则，从而减少漏报。大模型还可以通过代码理解和模式识别，帮助静态
分析工具发现潜在的漏洞模式。例如，大模型可以识别出某些代码片段中隐含的安全
问题，即使这些问题在传统的规则集中没有被明确描述。这种能力可以显著提升静态
分析工具的覆盖率和准确性。

在这一阶段，LLM 首先需要对漏洞报告进行深度且细致的解析，这不仅要求

定注释、特定的开发模式或习惯用法、以及容易被误识别的语义等。例如，对于SQL

全的编程框架和函数来处理数据库操作，这些因素都可能影响误报的判定。通过在设
计提示词时就明确这些误报标准，LLM 在后续的分析过程中就有了明确的判断依据，
能够更加准确地对漏洞进行分类和排查。LLM 会结合此前理解的漏洞报告信息和相
关代码上下文信息，运用其强大的逻辑推理和识别能力，分析和评估每一段可能受影
响的代码，它会检查代码中的输入验证逻辑是否完善，是否存在可能导致恶意攻击者
绕过的漏洞点，分析代码中的数据存储和传输方式是否符合安全规范，是否有数据泄
露或被篡改的风险等。

6.1.1 大语言模型与外部系统交互方法
方法调用(Function Calling) 功能允许模型识别用户需求并调用预定义的外部函
数或API，从而扩展模型的能力边界。当用户提出需要具体操作的请求时，模型可以
理解意图并自动选择合适的函数，按照正确的格式准备参数，然后触发函数执行并
将结果整合到对话中。这种功能使模型能够完成查询数据库、控制智能设备、进行计
算等实际任务，极大地增强了模型的实用性和应用场景。例如，用户询问天气时，模
型可以调用天气API 获取实时数据; 要求数学计算时，可以调用计算函数得出精确结
果。这种能力使大模型从单纯的对话系统进化为更实用的智能助手。
模型上下文协议（MCP）
[81]由Anthropic 于2024 年底提出，是一种开放标准，旨在
统一大语言模型与外部数据源及工具的通信，解决数据孤岛问题。其基于客户端-服
务器架构，包含MCP 主机（如Claude、Cursor、Cline 等AI 应用）、客户端通信模块和
服务器。MCP 支持模型安全访问本地文件、数据库、API 等资源，并调用代码生成、
网页抓取等工具实现自动化流程。例如，用户可通过配置服务器使Claude 直接创建
GitHub 仓库或查询PostgreSQL 数据。MCP 优势显著：标准化接口降低定制成本，服
务器端权限控制保障安全，加密通信强化隐私；同时支持混合访问本地与云端资源，
覆盖开发、协作、物联网等场景。目前该协议已集成至Claude、Cursor 等工具，并提
供开源服务器组件（如数据库连接器、网络工具库），推动AI 应用生态的互联互通。

据处理的准确性和效率，尤其对开发者而言，结构化输出的数据可直接用于对接其他
系统，减少二次解析成本。

6.1.3 LLM 应用开发框架
LangChain[86]是一个创新的大语言模型应用开发框架，它通过提供统一的接口和

包括Prompts 管理、LLM 接口封装、链式处理、智能代理和对话记忆等模块，不仅支

发者可以灵活组合各种组件来构建个性化的应用解决方案，如问答系统、聊天机器
人、文档分析和代码助手等，同时其标准化的接口设计和完善的文档支持显著降低了
LLM 应用的开发门槛，使其成为当前最受欢迎的LLM 应用开发框架之一。
LangGraph[87]是一个基于LangChain 构建的扩展库，旨在处理复杂的语言处理任
务。它通过引入图结构和有状态工作流（Stateful Workflow），支持循环、分支和动态
路径选择，特别适用于需要复杂流程控制的应用场景。LangGraph 的核心组件包括节

线性链式处理不同，LangGraph 提供了更细粒度的控制能力，能够处理多轮对话、条
件跳转和状态持久化等复杂任务。它广泛应用于对话代理、推荐系统、游戏开发和自
然语言处理等领域。

6.4 系统设计与实现
本系统主要包含交互层、决策层、执行层和整合层，各层模块之间通过标准化的

在架构实现上，各层次分工明确、协同工作：（1）交互层作为系统的人机交互门户，
采用基于自然语言处理的对话式交互模式，通过智能对话引擎实现与用户的多轮自

度等功能模块，能够将用户需求转化为可执行的任务流程；（3）执行层作为系统的操

具的协同工作；（4）整合层作为系统的输出终端，具备多源数据融合和智能报告生成
能力，能够将分散的分析结果整合为结构化的分析报告。
6.4.1 交互层设计与实现
交互模块是用户与系统进行交互的核心，具体功能包括：（1）需求接收与理解，

位置等）以及具体的检测需求（如重点关注的漏洞类型、遵循的代码规范等）。（2）对
话引导与管理，在与用户的对话过程中，能够根据用户的回答和上下文语境，智能地
引导对话流程，提出合适的问题以获取更全面准确的需求信息。例如，当用户未明确
指定代码语言时，系统可以主动询问相关信息。（3）结果展示与反馈，将系统的分析
结果以清晰易懂的自然语言形式呈现给用户，同时支持用户对结果提出疑问或进一
步的需求，如要求详细解释某个安全问题等，系统能够根据用户的反馈提供相应的解
答和补充信息。
6.4.2 需求分析与任务规划模块设计与实现

处理和语义分析技术，准确识别并结构化提取关键检测要素，包括目标代码类型（如

阵，采用任务分解算法将整体检测需求智能拆解为多个原子性子任务，并为每个子任
