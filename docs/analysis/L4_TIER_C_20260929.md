# Tier C 逐条追链记录（2026-09-29）

## 分诊结果：15 条 lead → 6 条有效（4 仓）、5 条克隆族、4 条输出方向（安全）

### A 类：有效候选（FFI 入口可达 + 输入侧消费 + 防护缺失）

#### 1. communication_bluetooth `CheckBleScanParams:221`（**有效**）

- **FFI 导出**：`FfiBluetoothBleStartBleScan(CArrNativeScanFilter filters, NativeScanOptions*, int32_t*)` (bluetooth_ble_ffi.cpp:59)
- **链**：FFI(:59) → `BleImpl::StartBleScan` → `CheckBleScanParams`(:221) → `for(i < length) { filters.head[i] }` **head 无 NULL 检查，size 无负值检查**
- **形态**：`static_cast<uint32_t>(filters.size)` 负 size 变 uint32 大正数 → 大循环读 head[i]——**比直接 null 更危险**（远程 BLE 扫描参数可控）
- **可达性**：应用侧蓝牙 API，`filters` 结构体由 Cangjie 调用方构造
- **验证**：需编 bluetooth CJ FFI 库（纯 C 调用即可，无 Context 依赖）

#### 2. web_webview `FfiOHOSWebMessageExtImplSetArrayDouble:512`（**有效**）

- **FFI 导出**：`FfiOHOSWebMessageExtImplSetArrayDouble(int64_t msgExtId, CArrDouble value, int32_t*)` (:512)
- **链**：FFI → `FFIData::GetData` 检查 msgExtId → type 检查 → `for(i < value.size) value.head[i]` **head 无检查**
- **形态**：需先创建合法 WebMessageExt 对象（`FfiOHOSWebMessageExtImplCreate`），构造难度中等
- **可达性**：WebView 消息扩展接口，应用侧可达

#### 3. graphic_graphic_2d `FfiEffectKitCreateColorPickerRegion:135`（**有效**）

- **FFI 导出**：`FfiEffectKitCreateColorPickerRegion(int64_t sourceId, CArrDouble region, uint32_t*)` (:135)
- **链**：FFI → `FFIData::GetData` 检查 sourceId → `for(i < region.size) region.head[i]` **head 无检查**
- **形态**：需先创建合法 PixelMap 对象，然后传 CArrDouble{null, 4}——region.head[i] 即 null 读
- **可达性**：图形效果 API，应用侧

#### 4. hiviewdfx_hiappevent `AddParams2EventPack:139`（**有效**）

- **FFI 导出**：`FfiOHOSHiAppEventSetEventParam(CArrParameters eventParams, char* domain, char* name)` (:416)
- **链**：FFI(:416) → `AddParams2EventPack(eventParams, ...)` (:422) → `for(i < params.size) { head + i; head->key; head->valueType }` **head 无 NULL 检查**
- **形态**：与 account/udmf/notification 同型——`CArrParameters.head` 为 NULL 且 size > 0 → 第一个 `head->key` 即崩
- **可达性**：HiAppEvent 打点 API，应用侧直接调用，**无任何前置对象创建**
- **验证最容易**：只需传 `CArrParameters{NULL, 1}` + 两个字符串即可

#### 5. hiviewdfx_hiappevent `FreeCArrParameters:31`（**有效但触发面窄**）

- 析构/释放路径中 size 控制循环释放 head[i]，head 为 NULL 时同样无检查
- 由 FFI 导出的 Write/AppEvent 路径间接可达（构造后释放）

#### 6. distributeddatamgr_relational_store `CArrStrToVector:520`（**有效但弱**）

- `for(i < carr.size) { if(carr.head[i] != nullptr) ...}` —— head 有逐元素 NULL 检查，但 **carr.head 本身（数组头指针）无 NULL 检查**。head=NULL + size>0 → `head[i]` 即空指针偏移解引用
- 调用链：`RdbStore::GetTableNames` / pluginLibs 解析 → 应用侧可达
