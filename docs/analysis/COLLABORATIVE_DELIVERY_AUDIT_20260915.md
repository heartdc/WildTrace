# 协作主线：静态交付离线复核与具体案例准备

## 范围与结论

本轮接续伙伴合并后的静态工具链，不增加标量/范围算法，不恢复 LLM。
先核对已有活动任务，待其结束后复用已生成的集成批次；未抢占、终止或
重复启动对方验收。等待期间在独立工作树进行只读文档检查和案例准备，
随后把两个新增文件以不覆盖方式移交主工作区，已核对字节一致。

当前成果是 **可独立复核的静态交付和候选验证准备**，不是带真实运行证据
的漏洞。伙伴提出的 W3 仍未完成，真实漏洞确认数为 0。

## 复用而非重建

`component-batch-0.2`、compiler事实绑定、队列/交接扩展和 `component_review`
首次运行入口来自同工作区的并行集成工作。其真实批次记录为
`.cache/integration_2b2e/final/acceptance.json`：camera3、securec39、hilog2，
共44个显式源文件，35条原始诊断、29个复核组、145项开放补证任务。

运行证据接收接口 `runtime_evidence` 和对应测试也由并行工作提供。
本轮复用它创建真实来源候选案例，并将其测试纳入回归；没有另造状态机或
把外部运行记录的完整性冒充执行真实性、授权真实性或漏洞确认。

## 本轮新增

`tools/component_review.py --verify` 以调用者显式指定的 manifest 和已有
输出目录为入口，重新检查最终批次、配置摘要、源码窗口、队列、交接和
status.json。输出路径从已知契约构建，不采用被篡改 receipt 中的任意路径。
验证不写文件、不启动分析器、不调用模型，创建模式依旧拒绝覆盖已有目录。

新增10项专门测试覆盖只读行为、错误状态晋升、路径伪造、源文件/配置变更、
重算外层摘要后的队列篡改、缺失/截断回执、校验中途变化及异常结构拒绝。
初版测试发现分析选择字段被误当成列表，已按实际嵌套字典契约修正后重跑。

候选 `AL-ENG-000008` 对应 securec `src/memcpy_s.c:518`。已生成并重建核对
`.cache/delivery_ccd71/final_r2/securec-review-case.json`，案例 ID 为
`RC-16d85aa85c309aa125e7b7c26763a2bdaf228e1393213d92d9bd8cddb2022df3`。
授权为 pending，安全影响未建立。源码检查发现复制前存在参数门控，不能
仅凭 memcpy 提示确认缺陷；仍需真实调用者的对象容量、输入来源和边界。
详细证据见 `SECUREC_MEMCPY_VALIDATION_CASE_20260915.md`。
