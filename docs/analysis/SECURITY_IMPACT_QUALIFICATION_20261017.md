# 空指针类新发现的安全影响定性（对赛题"普通 DoS 不纳入"条款的正面回应）

日期：2026-10-17
背景：赛题评价备注 4/6——"普通的 DoS 类问题若无实际安全危害或利用价值，不建议纳入
安全漏洞范畴"、"普通的 DoS 类、功能类等非传统意义的安全漏洞不作为安全类问题"。
本文档给出本案新发现（ipc / hiappevent / kv / udmf / bt#19）不属于"普通 DoS"的
定性论证，供作品报告、工单陈述与答辩引用。论证分层陈述，不越级主张。

## 一、"普通 DoS"条款的适用对象

"普通 DoS"指**资源耗尽或逻辑缺陷类**问题：算法复杂度爆炸、无限循环、连接/内存
配额耗尽、业务逻辑死锁等——其共同特征是**代码在语义上按设计运行**，缺陷在于资源
或逻辑层面，无内存安全破坏。

本案新发现全部不属于该类别：它们是 **CWE-476 空指针解引用**——内存安全缺陷的
标准类别（MITRE CWE-476 明确列为内存安全类，其后果除可用性外还包括潜在控制流
影响），触发形态是**畸形结构化输入穿过语言边界后对失效假设的直接解引用**。

## 二、两个层级的定性（按崩溃落点分层，不混淆）

### 层级 A：系统服务进程崩溃（bt#19 候选，最强形态）

- 崩溃落点：bluetooth SA 系统服务进程（libbluetooth_server.z.so，
  `bluetooth_socket_server.cpp:54`，gdb 帧归因 + 符号化实证）
- 触发面：任意第三方应用经 SAMGR 取得 socket 服务代理后发送一条畸形 IPC——
  **权限表为 nullptr（无权限要求）**，与 CONNECT/LISTEN 的双权限要求形成代码内
  自证（memberFuncMap_ 权限项）
- 定性：系统关键服务（蓝牙）的单请求远端崩溃，无认证、无权限、无用户交互。
  这不是应用自身健壮性问题，而是系统服务的输入验证缺失——与业界普遍接受为
  安全漏洞的"远端触发系统服务 SIGSEGV"同类。

### 层级 B：系统框架共享库中的边界内存安全缺陷（ipc / hiappevent / kv / udmf）

- 崩溃落点：消费方应用进程内加载的**系统框架 FFI 库**（libcj_ipc_ffi.z.so、
  hiappevent/kv_store/udmf 框架库）——真库 dlopen 复现 + gdb 帧归因实证
  （复现口径见各案 validation_evidence，`runtime_scope.open_harmony_binary_linked`
  如实标注 false，不冒充产品环境）
- 触发形态：仓颉类型系统的"非空、长度正确"保证在 FFI 对端失效，`{head=NULL,
  size>0}` 类畸形组合进入系统框架代码后未校验即遍历/解引用
- 定性三要点：
  1. **缺陷位于系统侧代码**，非应用自身逻辑——应用按公开 API 契约传入边界
     形态数据即可触发，受害面为全部使用该系统 API 的应用；
  2. **类别为内存安全（CWE-476/CWE-125）**，与资源耗尽类"普通 DoS"不同类；
  3. **边界审计真空是赛题立意的核心攻击面**——语言换代产生的跨语言信任边界
     缺陷正是本工具的题目定义（见作品报告第一章），将其排除将使该边界不可审计。

## 三、与生态惯例的一致性

- 上游 FFmpeg/cURL 等将 oss-fuzz 报出的空解引用/未初始化读取定为安全修复并发
  公告（本案 16 张 CVE 缺口单中的 CVE-2026-66037/IAMF 等即属分配类 DoS 形态，
  上游仍定为安全缺陷修复）；
- OpenHarmony 漏洞奖励计划的提交通道接受此类报告（五单均已按负责任披露流程
  提交，受理评审进行中——价值判定以平台评审结果为准，本文件不预支结论）。

## 四、陈述纪律（报告与答辩统一口径）

1. 不使用"远程代码执行"等未证实主张；CWE-476 的后果表述为"可用性破坏 + 潜在
   内存安全影响"；
2. 层级 A/B 分开陈述，不把应用进程崩溃说成系统服务崩溃；
3. 真库复现的环境边界如实标注（dlopen + musl 加载器，非整机产品环境）；
4. 最终价值以 OHSA 评审结果为准，报告引用"已提交 + 待受理"状态。

## 五、结论

五项新发现均为**跨语言/跨进程信任边界上的内存安全缺陷（CWE-476）**，其中 bt#19
为无权限要求的系统服务远端崩溃（层级 A），其余四项为系统框架 FFI 库的边界输入
验证缺失（层级 B）。两者均不属于赛题备注所指的"资源耗尽/逻辑类普通 DoS"，
应按内存安全漏洞类别参与评价。
