# Tier A/A- L4 追链记录（2026-09-29）

## av_session 9 条 lead 的实际链路（Tier A-）

**FFI 导出入口**（全部直传 CArray/CParameters*，无校验）：
- `FfiMultimediaAVSessionControllerSendCommonCommand(sessionId, command, CArray* args)` (:106)
- `FfiMultimediaAVSessionControllerSendAVKeyEvent(sessionId, CKeyEvent*)` (:125)

**调用链**（SendCommonCommand 路径）：
FFI(:106, CArray* args 直传) → SendCommonCommand(:200, 仅查 args.size==1) →
convertCJStructToNative(CArray, WantParams) (:1061, 仅查 size>0) →
SetDataParameters(CArray) (:234, **仅查顶层 head!=nullptr**) →
按 valueType 派发 → Inner*Array* 系列 → charPtrToVector(value, size) → **无检查循环**

**关键发现**：这是比 IPC 更深一层的同型缺陷——顶层 `CArray.head` 有空检查，但
每个元素 `CParameters.value`（指针类型的嵌套数组头）在派发到 Inner*Array* 时
**不检查是否为空**。攻击路径：

```
Cangjie 调用方构造：
CArray{ head: [CParameters{ valueType=STR_PTR_TYPE, value=nullptr, size=5, key="x" }], size=1 }
→ SendCommonCommand size==1 通过 → SetDataParameters head!=nullptr 通过
→ InnerSetWantParamsArrayString → charPtrToVector(nullptr, 5) → 循环读 null[i] → SIGSEGV
```

9 个 Inner* 中可由此路径触达：ArrayString(:149)、ArrayInt(:167)、ArrayBool(:184)、
ArrayDouble(:201)——4 条；HashMap(:274) 递归到 SetDataParameters 有同样的嵌套
问题；ArrayFd(:437/498) 需单独确认 FD 类型路径。

**扫描器误报澄清**：OnEventCallMetadataChange/StateChange/PlaybackStateChange
三条 lead 为误报——控制器事件注册路径有完整防护（null/valueType/size 三重检查，
:267-273）。Tier A- 实际有效 lead 为 6 条（4 Array* + 1 HashMap + 1 待确认 FD），
非 9 条。
