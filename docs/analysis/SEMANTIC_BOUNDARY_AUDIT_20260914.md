## 已修复的问题

旧 `semantic_rules` 可能把下一个函数的复制操作关联到前一个函数；仅解析
单行、遇到第一个右括号就停止；snprintf格式串被当成长度；同一行多个调用
可能复用第一次匹配；重复函数名采用最后一个定义；调用者的来源行用call-1猜测。
同时，覆盖率由有告警文件推算，读取时替换非法UTF-8，主CLI把语义阶段硬写为完成。

新增 `semantic_syntax` 并重写规则，使用同一批有界源码字节、函数体范围、平衡
括号和实参位置；来源及未知事项分离，两个关联文件的摘要保留。主CLI接入执行
记录，并在发布前再次核对显式文件清单。所有候选仍需安全分析，CWE不再默认120。
