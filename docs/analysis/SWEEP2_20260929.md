# 第二轮模式扫描 + 嵌套深挖报告（2026-09-29）

## 四个新模式族扫描结果（491 文件 × 4 模式 = 73 lead）

### F1 嵌套数组解引用（5 条）——最高价值

#### hiappevent `AddWatcher:376-385`（**有效，双嵌套**）

```cpp
for (int i = 0; i < watcher.appEventFilters.size; i++) {
    for (int j = 0; j < watcher.appEventFilters.head[i].names.size; j++) {
        names.insert(std::string(watcher.appEventFilters.head[i].names.head[j]));
    }
    // ...
    for (int k = 0; k < watcher.appEventFilters.head[i].eventTypes.size; k++) {
        types |= (BIT_MASK << watcher.appEventFilters.head[i].eventTypes.head[k]);
    }
}
```

**三层防护全缺**：
1. `appEventFilters.head` 为 NULL → 第一个 `head[0].names` 即崩
2. `head[i].names.head` 为 NULL → 内层 `names.head[j]` 即崩
3. `head[i].eventTypes.head` 为 NULL → 同上

**另有算术左移 UB**：`BIT_MASK << head[k]`，若 head[k] 为大负数/大正数，移位超 31 位为 UB。

FFI 导出 `FfiOHOSHiAppEventAddWatcher(CAppEventWatcher watcher)` 直传整个结构体。

### F2 malloc 算术溢出（3 条，低优先——需极大 size）

分配 `sizeof(X) * size` 的乘法溢出需 size > 2^32/sizeof，在应用侧 API 不太实际。降级为边界质量观察。

### F3 字符串无界构造（58 条，广但浅）

`std::string(char*)` 不查空指针。大量命中但多数是 null 检查在调用方而非本函数。
集中度最高的是 global_resource_management（20 条）——需逐条看调用方是否有防护。作为第二轮优先级最低。

## bluetooth 深挖补充发现

1. **serviceData 空 vector 逻辑 bug**（:173-181）：`if (head != nullptr) SetServiceData(空vector)` 
   —— head 非空时设了空数据，head 指向的数据从未读入。**逻辑错误（数据丢失），非内存安全**
2. **ParseManufactureDataParameters:314**：`parameter.head[i]` 外层无检查 + 
   `manufactureValue.head` 内层无检查 + `std::string(ptr, size)` 负 size→size_t 大正数 → 
   **三重漏洞同函数**
