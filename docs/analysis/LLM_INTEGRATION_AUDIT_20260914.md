## 已落地的实现

- `ohvul/llm_adapter.py`：固定 HTTPS 端点范围、指定模型标识、禁止重定向、
  单次请求无自动重试、输入/输出大小限制、凭据筛查、错误码脱敏，保留正常
  TLS 验证。旧 `draft_analysis` 调用入口仍可使用。
- `ohvul/llm_review.py`：`--plan` 不调用网络；`--run --allow-network` 才发起
  显式选择的模型请求；`--verify` 仅做本地重建校验，不调用模型。
- 每组请求只有相对源码位置、代码窗口和诊断引用，不上传整仓、分析器命令、
  绝对工作区路径、比赛文档或凭据。证据文本明确为不可信数据，不可定义工具。
- 输出必须完整回答既有五个问题，观察需引用当前组的行/诊断 ID；伪造引用、
  不完整输出、异常模型标识、重复问题、未知字段或直接确认漏洞均被拒绝。
- 结果是待人工审核的建议，不能执行命令、删除候选或改变 FSM。
  `final_verdict=undetermined`，确认漏洞数始终为零。
- 记录精确输入与提示摘要、请求/响应摘要、请求及返回的模型标识、有限用量
  字段；缺少用量是未知，不是实际消费为零。
- 在本次 403 实测后补充熔断：一次传输错误后，剩余选择明确记为 `not_run`，
  不继续付费请求、不自动重试，也不混淆失败数与未调用数。
