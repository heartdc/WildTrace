## 已经从源码确认的事实

`src/memcpy_s.c:478–484` 的两个参数检查宏均要求 `count <= destMax`、
源和目标非空、`count > 0` 以及相应非重叠条件；非 Windows 兼容分支还
检查最大许可长度。`src/memcpy_s.c:515–522` 的正常复制位于该条件成立
的分支。`src/securecutil.h:222–230` 显示其后端可能是 `memcpy` 或
`memcpy_opt`，取决于宏配置，不能把所有配置的后端混为一谈。

`src/memcpy_s.c:445–471` 显示错误处理有返回码和清零动作。清零长度
来自调用者提供的 `destMax`。源码注释在 `src/memcpy_s.c:491–495`
把 `destMax` 描述为目标缓冲区大小；这不是编译器已经证明的实际分配容量。

因此：`count <= destMax` 不能单独证明 `destMax` 与真实容量一致；反过来，
人为把实际小对象冒充大对象传入 API，也不能直接证明该库自身存在漏洞。
还需要真实调用路径、参数来源和适用接口约定，而不是仅制造一次崩溃。
