# Tier B 克隆族 L4 追链记录（2026-09-29）

## 核心发现：三仓克隆族确认，与 av_session 同型但**浅一层**（更危险）

Tier A-（av_session）的缺陷形态是"嵌套 value 指针不查空"（第四层）。
Tier B 的 account_os_account 和 udmf 是**同一份代码的拷贝**——但它们的
`SetDataParameters` 连顶层的 `head` 都不查空（第三层就缺防护）。

### account_os_account（5 条 lead）

**调用链**：
`FfiAppAccountAppAccountManagerCreateAccount(id, name, CCreateAccountOptions)` (:37)
→ `CreateAccount(cOptions)` → impl:524 `SetDataParameters(cOptions.parameters, ...)` 
→ parameter_parse.cpp:163 **直接进循环，无 head null check**

**防护缺失层级对比**：
| 组件 | head null | head->value null | valueType guard | size guard |
|---|---|---|---|---|
| av_session | ✓ :237 | ✗ ←死在这 | 派发 | ✗ |
| account | **✗ ←死在这** | ✗ | 派发 | ✗ |
| udmf | **✗ ←死在这** | ✗ | 派发 | ✗ |

account 的 `SetDataParameters`(:163) 从 `for (int i = 0; i < parameters.size; i++)`
直接开始——`parameters.head` 为 NULL 且 `parameters.size > 0` 时，`head + i` 就是
空指针算术，第一个 `head->key` 即解引用崩溃。**比 av_session 浅一层，更直接。**

**ABI**（appaccount_defination.h）：
```c
typedef struct { int8_t valueType; char *key; void *value; int64_t size; } CParameters;
typedef struct { CParameters *head; int64_t size; } CArrParameters;
typedef struct { CHashStrStrArr customData; } CCreateAccountOptions;  // 顶层入口
```

impl 用的 `cOptions.parameters` 来自 `CAccountCreateOptions`(:106)，包含
`CArrParameters parameters / properties` 两个字段——两个都是直接可达。

### udmf（4 条 lead）

**调用链**：
`FfiUDMFSetDataProperties(unifiedDataId, CUnifiedDataProperties*)` → unified_data_ffi.cpp:132
→ `SetDataParameters(properties.extras, wantP)` → parameter_parse.cpp:158
→ **同样无 head null check，直接 `head + i` 循环**

udmf 的 `UINT8_ARRAY_TYPE` 分支还有 `std::vector(uint8_t*, uint8_t*+size)` 
**负 size 迭代器下溢 UB**（与 av_session ArrayInt 同型）。

### 克隆关系

三仓的 `SetDataParameters`/`InnerWrapWantParams*`/`charPtrToVector` 函数名和
结构完全一致（变量名微异），显然是同一模板拷贝到不同组件。这意味着：
- 任一仓修复时其他仓大概率不会同步（OH 的 CJ 组件各自独立维护）
- **如果一个实例被证实，三仓全族都是候选**

## 提交策略

Tier B 比 Tier A- **更容易验证**（浅一层=直接 null 算术，不需要构造特定
valueType），且 account 和 udmf 的 FFI 入口同样**无 AbilityRuntime 依赖**：
- account: `FfiAppAccountAppAccountManagerCreateAccount` 直接接受 options 结构体
- udmf: `FfiUDMFSetDataProperties` 直接接受 properties 指针

建议：与 av_session 同批验证（对侧任务书追加 F 节），证实后 account/udmf
各自独立提交工单。三仓克隆族合计潜在新发现 = av_session 6 + account 5 +
udmf 4 = **15 条批量候选**。
